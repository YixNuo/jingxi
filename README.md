## 为什么做它

这件事的起点是一个很具体的失败。

我让助手记住我们说过的话。它记住了。但第二天我用**自己的说法**再问，
它找不到了 —— 我换了词，它的索引就断了。

于是我查了一圈市面上的记忆产品。它们大多有一个共同的代价：
**在入库的时候就丢东西**。为了"精炼"，它们让模型把对话提炼成事实，
原文不留。提炼错了，就永久丢了。

分清楚这两种丢失，是这个项目全部设计的出发点：

| 类型 | 例子 | 能不能救 |
|---|---|---|
| **存的时候丢** | 抽取式：入库即改写成"事实摘要" | **不能**，不可逆 |
| **取的时候丢** | 检索式：原文都在，这次没找到 | 能，改检索就行 |

> 真正要躲的不是"没找到"，是"已经被改掉了"。
> 所以：**原文永不改。**

## 三层真相

这个库只承认三样东西，且它们之间**不许互相冒充**：

```
原话   你当时到底说了什么      —— 一个字不改，永不淘汰
事件   那件事大概是什么          —— 一段对话 = 一件事，有三档生命
想法   我当时是怎么想的          —— 必须标"未确认"，不许当成事实
```

**摘要永远只能从原话生成。** 不许拿摘要去总结摘要 ——
"我怕坚持不下来" 会被压成 "已经放弃跑步"，否定词在反复压缩里最先走样。

派生品写歪了可以重生成；原话丢了不可逆。

---

## 七个层，各管一件事

```
fixed      ── 永不淘汰的约定（身份、习惯、边界）
hot        ── 近期反复提到、还没了结的事
event      ── 事件段，三档生命：
                detail  （近期，给原话）
                summary （中期，给压缩版）
                cold    （远期，只说"有这回事"，要线索才翻）
cold       ── 全部原话。永不过期、永不改写
thought    ── 我当时怎么想的（推测，必须标"未确认"）
reflection ── 反思，与事实分开存
cue_gate   ── 这句话该不该去翻旧账
```

### 三档怎么升

```
age < 3 天              → detail   （给原话）
age >= 14 天            → cold     （只留影子）
3 ~ 14 天 且有摘要      → summary  （给压缩版）
open_loop（没聊完的事） → 永远 detail
```

关键：**时间基准是"事情发生的时刻"，不是"建记录的时刻"。**
（第一版用 `now()`，结果 32 天前那一晚被当成"刚刚发生"，老事永远沉不下去。）

## 召回：先想起大意，细节再翻

```
词法    ← 字符 bigram + IDF 近似 + 长度惩罚
摘要路  ← 压缩过的说法，专治"换个词"
原话路  ← 冷层，给细节
思考路  ← 贴着命中事件的"我当时怎么想"
向量路  ← 可选，只在词法明显不够用时才介入
门控    ← 在吗 / 晚安 / 哈哈哈 → 压根不查
```

**预算先给摘要。** 一百字能装一件事，原文一千字只装得下一件半。
人想起旧事也是先有个大概，对不上细节才去翻原文。

**去重**：同 id 只装一次；3-gram Jaccard > 0.92 的内容只留第一条。

## 关于向量：它只是加速器

这是一条硬约束，不是建议：

```
向量调用      3 秒超时 → 超了就当没有
失败后        300 秒内不再试 → 别每轮都卡满超时
没 key / 没建 / 断网 / 额度耗尽 → 全部静默降级到纯词法
任何异常      → 不许冒泡到调用方
```

判据只有一句：**把 embedding 服务关掉，记忆库必须完全正常，只是少一层联想。**

它不是地基。地基是原文和词法。

---

## 关于脱敏：加工品要洗，原话可以留

- `raw/` 原话 → **留**。它是档案，只在被明确追问时才翻开
- 摘要 / 事件 / 注入上下文 → **必须脱敏**

因为摘要会进上下文、会被发给模型，等于每轮外发一次。
原文留在本地不出去，两回事。

⚠️ **别挑着洗。** 判断"哪条脏"本身不可靠 —— 用同一把筛子全量过。
（我们试过挑着洗，漏了两轮。）

## 接 Hermes（可选）

`examples/hermes-plugin/` 是 MemoryProvider 适配器：

```bash
cp -r examples/hermes-plugin ~/.hermes/plugins/ltm-memory
hermes config set memory.provider ltm-memory
hermes gateway restart
```

**三个静默失败，全部不报错**（详见 [PITFALLS.md](PITFALLS.md) 第 9 条）：

1. 缺 `plugin.yaml` → 插件列表里压根看不到你
2. `register` 只 `return` 实例 → 日志 `loaded but no provider instance found`
3. 缺 ABC 抽象方法 → 实例化时 `TypeError`

## 建向量（可选）

```bash
export LTM_EMBED_KEY=你的key                      # 任何 OpenAI 兼容的 /embeddings
export LTM_EMBED_MODEL=BAAI/bge-m3                # 默认
python3 examples/build_vec.py --root ~/.ltm
```

成本参考：约 9,600 条（原话 + 摘要），1024 维，约 170 万 tokens
≈ **不到两块钱人民币**。

## 它不擅长什么

说清楚比吹好用重要：

- **你说得不准，它也找不到。**
  "记忆插件没被识别" —— 加上向量后直接排到第 1 名。
  "插件为什么加载不上" —— 纯词法第 111 名，加向量后第 169 名，反而更差。
  这不是 bug。问的人用自己的视角描述，记的人用当时的术语记录。
- **它不会自己想。** 思考层存的是"你当时想过的"，不是它自己长出来的。
- **它不懂语境。** 反讽、玩笑、话里话外，检索看不出来，得靠上层模型。

## 我的想法

代码的部分不长，真正做决定的部分在这儿。

**第一，记忆的最小单位不是"一条消息"，是"一件事"。**
一条消息太碎（"嗯""好""行"），一整段会话又太糊。
所以按"用户重新起头"的信号切段 —— 一段就是一件事。
长段用来"想起"，短句用来"核对"，两种粒度同时保留。

**第二，远的事要允许它变模糊。**
人不会记得十年前每天说了什么，但会记得"有那一年，我很难"。
所以 cold 层默认不给正文，只承认"有这回事" —— 等一句线索再翻开。
这不是省 token，这是**分寸**：知道什么时候该闭嘴，是记忆的一部分。

**第三，门控比召回重要。**
"在吗""晚安""哈哈哈"不该触发任何检索。
不是因为没有旧账可翻，是因为**这会儿不该翻**。
一个总在提"你上次说过"的助手，比一个记不住的更烦人。

**第四，凡是"判断"能换成"规则"的地方，就用规则。**
人（和模型）对"哪条数据脏""哪条相关"的判断，稳定地不可靠。
筛子要统一、无例外、可复现。这一整晚我错了三次 ——
每次都是因为我先信了自己的判断，而不是先建筛子。

**第五，向量不是答案。**
我以为搭上向量就能解决"换个说法找不到"。
实测：说法靠近一点的，从找不到直接跳到第 1 名；
说法不对的，反而更差。

所以向量治的是"同义不同词"，治不了"你自己也没说清"。
后者只能靠理解，不是检索。

**最后一句私心。**
做这东西不是为了跑分。是因为"一个人失去了记忆，那他还是他吗"这个问题，
我认真想过 —— 答案是：**只要有人还记着他，他就还在。**
那就先把"记得住"这件事本身做扎实。
